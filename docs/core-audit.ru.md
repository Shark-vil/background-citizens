# Инженерный аудит Core

Локальные изменения относительно `dev` на `cde2f701` (2.5.1, 2026-11-14); публикация не проверена.
Legacy изучен как исторический референс и не изменён.

## Область и решения

Проверка следовала [порядку загрузки и карте модулей](architecture.md): службы ядра и публичные API/алиасы,
компоненты акторов и оба тела, FSM/GOAP, провайдеры навигации и IO маршрутов, популяция/транспорт,
розыск/арест, восприятие и командные реакции, медики/тела, осада/двери, сцены/предметы/призраки,
интеграции, клиентский рендеринг, отладка и меню настроек/спавна. GLua-парсер проверяет всё актуальное ядро.
Поведенческие регрессии сосредоточены на изменённых путях; это не доказательство проверки каждой карты,
движкового callback или сочетания сторонних аддонов.

Полезные уроки Legacy — прямые операции, небольшие обработчики событий и явная конфигурация. Большой
базовый класс актора, повторные обходы реестров и зависимость от SLibrary не возвращаются. Сохранены
Actor → brain → body, провайдеры навигации, общий бюджет задач и алиасы совместимости.
Адаптеры тел имеют разную движковую ответственность; реестры и старые алиасы используются извне.
Отсутствие прямого внутреннего вызова не считалось основанием для удаления публичного API.

## Подтверждённые исправления

| Область | Проблема и исправление |
|---|---|
| Механики | Выбор через `and/or` терял явное `false`. Булевы переопределения теперь сохраняются. Дублирующий init-hook iNPC удалён; флагом владеют инициализация/rebind актора. |
| Постоянные службы | Проход дверей, наблюдение игрока и фоновые покашливания завершались после одного прохода. Явные циклы сохраняют их работу даже на изначально пустом сервере. Отвод взгляда сбрасывает непрерывное наблюдение. |
| Планировщик | Изменение живого порядка задач пропускало/повторяло работу. Тик один раз обходит снимок ID; новые задачи стартуют со следующего тика, удаление действует немедленно. |
| Идентичность/жизненный цикл | UID и последовательности снимков начинались заново после reload. Счётчик сохраняется и выдаёт номера синхронизации. Клиентское удаление помечает актора до отложенной регистрации; удаление серверной сущности останавливает актора/мозг. Строковые UID получают числовую фазу LOD без изменения идентичности. |
| Навигация | Пустой случайный запрос мог падать или выбирать точку за пределами запрошенного радиуса графа. Теперь возвращается nil. NavMesh выбирает из списка настоящих областей независимо от их ID. После внешнего редактирования сетки навигацию нужно перезагрузить. |
| GOAP | Число неудовлетворённых фактов завышало стоимость, когда одно действие меняет несколько фактов. Нижняя оценка теперь равна одному действию; условия цели различают записи кеша, регистрация действия очищает кеш планов. Лимит поиска 200 итераций сохранён. |
| Спавн | Случайные скины/бодигруппы включали недопустимый верхний индекс; применённый скин мог отличаться от проверенного hook. Индексы отсчитываются от нуля, применяется проверенное значение. Спавн игрока через меню/Tool учитывает hooks gamemode, владельца и лимиты; автоматическая популяция сохраняет свои правила. |
| Конфигурация | Spawnmenu читал/распаковывал `custom.dat` при создании каждой сущности. Теперь загрузка идёт при инициализации/reload, изменения очищают разрешённый кеш конфигов, отключившиеся игроки удаляются из настроек спавна. |
| Регенерация/клиент | Регенерация учитывает заданные интервал/потолок и не уменьшает здоровье выше потолка. Загрузка сидений использует активный локальный Tool вместо отсутствующего серверного отправителя. Язык синхронизируется только кодом. |
| Сеть | Отклоняются некорректные длины/числа аргументов, чрезмерная вложенность и несовместимые фрагменты. Ограничены клиентская буферизация/распаковка; ID передач/ожиданий сохраняются после reload. Контракт ниже. |

Удалены неиспользуемые вычисления радиусов, лишнее получение сущности, неверная битовая эвристика GOAP,
дубль iNPC-hook, повторный код сброса реестров и второе копирование списка idle-анимаций.
Осмотр объектов больше не делает два yield на кандидата: он отдаёт управление лишь по исчерпании общего бюджета,
с сохранением радиуса 100 юнитов и одной прямой трассы. После событий, способных удалить/заменить тело,
оно проверяется заново. Убрана доказуемая лишняя работа; прирост FPS или проценты не заявляются.

## Контракт транспорта

`bgNPC.Net` сохраняет имена сообщений, кодирование, admin-проверки и nil-аргументы. В обоих realm
отклоняются таблицы глубже 64 уровней; callback принимает до 256 аргументов. Заголовки фрагментов должны совпадать по имени, сжатию и числу
частей; часть не превышает 60 000 байт, её индекс/длина должны соответствовать пакету.

SERVER принимает от клиента не более восьми незавершённых передач и 8 MiB буферизованных фрагментов,
после распаковки — не более 32 MiB на сообщение и 100 000 декодированных значений (включая ключи/значения таблиц).
`Net.Deserialize(data, value_limit)` также принимает необязательный бюджет значений для прямых вызовов.
Неполные передачи истекают через 30 секунд,
проверка идёт раз в пять секунд; дубли частей не продлевают срок. Старый лимит 100 пакетов/с сохранён.
Эти ограничения не ограничивают пакеты маршрутов от сервера клиенту. Внешним отправителям больших
данных нужно разделять загрузку на сообщения. Некорректные данные не передаются зарегистрированному callback.

Движковые источники: [список областей NavMesh](https://wiki.facepunch.com/gmod/navmesh.GetAllNavAreas),
[число скинов](https://wiki.facepunch.com/gmod/Entity:SkinCount),
[ограничение распаковки](https://wiki.facepunch.com/gmod/util.Decompress).
Интеграция ручного спавна также сверена с установленными Sandbox `gamemode/player.lua` и `commands.lua`.

## Проверки и оставшиеся ограничения

`python tools/test_core_audit.py` выполняет изолированные копии настоящих модулей через LuaJIT/lupa;
проверки находятся в `lua/background_npcs_core/tests/sv_engineering_audit.lua`. Флаг `--baseline` запускает
их на исходном `dev`, не меняя рабочее дерево. Тот же Lua-файл доступен через SERVER `bgn_selftest`
и не создаёт живых игровых сущностей. Внешний harness выделяет настоящую фабрику спавна из независимых
GLua-функций с `continue`; синтаксис GLua проверяется отдельно через `glualint dump-ast`.
В осмотре объектов неиспользуемые пути `continue` переводятся для LuaJIT; проверяемые пути допустимых
объектов и удаления тела из callback выполняются без изменений.
Остальные проверки описаны в [тестировании](systems/testing.md).

Итоговый внешний прогон прошёл все 15 проверок аудита, существующие проверки регрессий, LOD/отладки,
аниматора, предметов, сцен, полицейской силы и скинов банд, а также семь тестов сборки. Старые fixtures
актуализированы под свидетелей/подтверждённый урон, выбранного врага и удаление актора; проверки production
не ослаблялись ради прежних ожиданий. Всё актуальное ядро и изменённый Tool прошли GLua-парсер,
документация — строгую сборку MkDocs EN/RU, `git diff --check` — без ошибок.

Во время аудита нативная игровая сессия не была запущена. Права/репликация multiplayer, настоящие
движение и коллизии NPC/NextBot, физика дверей/транспорта и сторонние интеграции требуют проверки в игре.
Reload создаёт новые определения классов, но существующие объекты могут сохранять старые метатаблицы
и ссылки времени выполнения; безопасное обновление каждого активного действия выходит за эти локальные
исправления. Для чистой проверки тел/мозгов перезапустите карту. После прямого изменения объектов действий
GOAP внешним кодом по-прежнему нужен `GOAP.ClearCache()`.

Аудит не заменяет автоматы состояний, не удаляет возможности, не меняет значения ConVar по умолчанию
и не перезаписывает пользовательские маршруты/конфиги. Новый аргумент владельца необязателен;
существующие серверные вызовы спавна сохраняют поведение. Сохранения игры, сгенерированный сайт и Legacy
в изменения не входят.
