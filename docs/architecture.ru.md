# Архитектура проекта

База документации: **2.3.1**, ветка `dev`, коммит `7459c3c7` (2026-11-10). Тег `2.3.0` — `2258b49`; изменения после него выделены в [истории](history.md). Описание относится к репозиторию: оно не означает, что все коммиты уже опубликованы в Workshop.

## Области выполнения

| Область | Ответственность | Загрузка |
|---|---|---|
| Сервер | Популяция, тело/мозг, ИИ, навигация, урон, розыск/арест, медики, провайдеры транспорта | `sv_` и серверные ветви `sh_` |
| Клиент | Меню, голоса/субтитры, визуальная толпа, HUD розыска, редактор/отладка | `cl_` и клиентские ветви `sh_` |
| Общий код | Классы, конфигурация, определения API, сериализация, полученные записи акторов | `sh_`; данные каждого Lua-окружения независимы |

Префикс файла определяет загрузку, а не возможность управлять NPC на клиенте. См. [справочник по областям](reference/shared.md).

## Порядок загрузки

`lua/autorun/background_npcs.lua` отправляет и включает `background_npcs_core/sh_init.lua`. Загрузчик сортирует файлы, обходит в каталоге `sh_`, `sv_`, `cl_`, затем подкаталоги; повторные явные включения исключаются. Языки реплик и переводы опций меню подключаются вручную.

1. Ядро: уведомления, классы, сеть, утилиты, планировщик, остальные помощники.
2. Конфигурация, акторы, реплики, состояния; пользовательский `config`, адаптер старого конфига.
3. API, cvars, команды; пользовательский `preload`, снимок настроек по умолчанию.
4. Класс актора, компоненты, адаптеры тела, события, обновление, синхронизация.
5. Навигация, провайдеры, ввод/вывод; провайдер DV.
6. Команды/розыск, модуль ареста, остальные системы; мозги, спавнеры, интеграции.
7. Языки меню, интерфейс, отладка; пользовательский `postload`, `BGN_PostLoadScripts`.

Порядок важен: обработчики нарушителей и состояний сохраняют ссылку на зарегистрированный модуль ареста. `bgn_scripts_reload` повторяет загрузку; для чистой проверки изменённых тел и состояния мира нужна перезагрузка карты.

## Файлы и ответственность

Пути ниже относительно корня репозитория. Внутри `lua/background_npcs_core/`:

| Путь | Назначение и связи |
|---|---|
| `sh_init.lua` | Версия, хранилища, порядок загрузки. |
| `core/` | Классы, бюджет задач, сетевой кодек/чанки, cvars/команды, самопроверки, уведомления, утилиты. |
| `config/` | Настройки; `actors/` — типы/наследование, `states/` — данные диалогов/сцен/ареста, `replics/language/` — реплики/голоса. |
| `custom_modules/config`, `preload`, `postload` | Этапы расширения; файлы отдельного аддона доступны через объединённые Lua-пути GMod. |
| `api/` | Реестры акторов, конфиг, точки, состояния, режимы, видимость, статистика, проверки, бой. `compat/sh_legacy.lua` — старые вызовы через двоеточие. |
| `cvars/`, `commands/` | Регистрация настроек, значения по умолчанию, административные действия. |
| `actor/sh_actor.lua`, `components/` | Идентичность/здоровье/жизненный цикл; состояния, враги, цели, команды, движение, оружие, анимации, речь, транспорт. |
| `actor/body/` | Серверные адаптеры NPC/NextBot к движку. |
| `actor/update`, `events`, `sync` | Обновление симуляции, урон/смерть/сохранение, сетевые снимки и привязка клиента. |
| `nav/` | Фасад провайдеров, граф/A*, custom/navmesh/nodegraph; `generator/` — генерация, `io/` — редактор/сохранение/компиляция/дубликации, `legacy/` — конверсия. |
| `brain/fsm/`, `brain/goap/` | Выполнение состояний и планирование боя; состояния вызывают Actor, тело выполняет движковые действия. |
| `spawner/` | Проверки видимости, создание/рециклинг популяции, отдельные радиусы машин, подкрепление погони, очистка. |
| `systems/` | Розыск/арест, нарушители, медики/тела, команды/общие враги, состав боя/пауза/группы банд, диалоги, сиденья, сцены, толпа, режимы. |
| `modules/` | Необязательные интеграции DV, DarkRP, StormFox, NPC-моды. `dv/` — доступ, манёвры машин, обход пешеходами, возврат, урон. |
| `ui/` | Меню настроек, Classic-панели, мастер/приветствие, spawnmenu, обновления, переводы. |
| `debug/` | Оверлей администратора, диагностика/камера, визуализация движения, игровые автопроверки. |

| Путь | Содержимое |
|---|---|
| `lua/entities/` | NextBot и сущности/контроллеры DV; область задают init/shared/client-файлы сущности. |

## Взаимосвязи

```text
config -> кеш разрешённых Config -> копия конфига конкретного актора
навигация + видимость игроков -> спавнер -> реестр Actor
Actor -> мозг FSM/GOAP -> callbacks состояния -> методы Actor -> тело -> сущность движка
системы/события -> реакции / розыск / арест / вызов медика -> переход состояния
Actor <-> провайдер транспорта -> контроллер DV + шасси + визуальная модель пассажира
серверный Actor -> снимок PVS + поколение -> клиентский реестр -> интерфейс / звук / рендер
```

Посадка сохраняет актора и UID, но заменяет сущность и адаптер тела. Реестры, ссылки врагов/целей, розыск и статистика следуют за заменой. Собственные данные стороннего аддона переносите через `BGN_ActorEntityChanged(actor, old, new)`.

Удерживанием двери управляет сервер (`systems/sv_door_hold.lua`, `brain/fsm/states/sv_hold_door.lua`), действие
выбирает GOAP. Временное `knocked_down` сохраняет исходную сущность и адаптер тела, скрывает/замораживает их,
а серверный регдолл обеспечивает физику и передачу урона. Цикл обновления актора выполняет только восстановление;
для подъёма нужен свободный хитбокс. Синхронизация и клиентская оптимизация отрисовки сохраняют серверный флаг скрытого тела.

`debug/sv_scenic.lua` отвечает за админское размещение сцен, владельцев/Undo и один цикл проверки двери GOAP.
`lua/weapons/gmod_tool/stools/bgn_scenic_debug.lua` даёт выбор сцены и HUD осмотра через существующий Tool RPC
с сервера на клиент. При ручном создании и отложенной постановке проверяется администратор-владелец; только этот
путь обходит проверку скрытой позиции. Модели всех акторов по-прежнему определяют обычный спавнер и его хуки.

`systems/sh_carry_items.lua` содержит общие определения предметов, проверки моделей/анимаций и выбор по шансу.
SERVER управляет временем жизни предметов настоящих акторов; адаптеры тел исключают
эти предметы из запросов боевого оружия. Для переноски используются только таблицы активностей NextBot.
Ходьба HL2 NPC не меняется; CLIENT крепит кейс к кости руки на обоих типах тела. Кейс не становится физическим объектом. `systems/cl_carry_items.lua` управляет клиентскими
предметами настоящих акторов через `carry_visual` в существующих PVS-снимках. Газета скрывает паёк NextBot,
управляющий позой, и располагает штатную модель бумаги между обеими кистями. Призраки и появляющиеся из них акторы всегда без предметов. Размещение сцен остаётся на SERVER, включая
трассировки комнат/уступов, габариты мебели и целостность пары на диване.

## Настройки и данные

Значения cvars — в `cvars/sh_cvars.lua`, `sv_cvars.lua`, `cl_cvars.lua`; инфраструктура прав/регистрации — `core/sh_cvars.lua`. Серверные настройки меняют администраторы, голоса/интерфейс локальны. Конфиг разрешает `inherit` и `@type`, кешируется, копируется при создании актора. После правок определения очищайте кеш; существующие акторы сохраняют свои копии.

Пути DATA относятся к `garrysmod/data/`, а не каталогу аддона: `background_npcs/nodes`, `graph`, `seats`, `compile` (создаёт загрузчик), отчёт `background_npcs/test_report.txt`. Точки DV отделены от пешеходных. Сохраняйте пользовательские маршруты; импорт старых данных/дубликаций не должен затирать посторонние точки. Скомпилированные маршруты — генерируемые Lua-файлы для распространения.
